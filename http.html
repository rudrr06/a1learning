HTTP Request & Response

Every web page is a conversation of requests and responses. Watch one load, including a missing file.

What just happened?

The step you are on lights up here.

  1. 1. Request – A method (GET, POST…), a path and headers.
  2. 2. Response – A status code, headers and a body.
  3. 3. More requests – One page triggers many requests (CSS, JS, images).
  4. 4. Errors – 4xx means the client asked for something wrong, 5xx means the server failed.

Why it matters

Common methods: GET (fetch), POST (send data, like a form), PUT (replace), DELETE (remove). Common codes: 200 OK, 301 moved permanently, 401 login needed, 403 forbidden, 404 not found, 500 server error.

HTTP is stateless: each request is independent, so sites use cookies and tokens to remember who you are. Anyone who steals your session cookie can act as you.

Security link: plain HTTP is sent as readable text, so anyone on the network (like on public Wi-Fi) can read it. HTTPS fixes that (see the next topic). Web hackers live in these requests: intercepting and editing them with tools such as Burp Suite is the core of web security testing and bug bounty hunting.
