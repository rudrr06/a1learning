DHCP

When you join Wi-Fi, you do not type an IP address. Watch how the network hands you one.

What just happened?

The step you are on lights up here.

  1. 1. DISCOVER – The new device broadcasts to find a DHCP server. This is a broadcast because it has no IP yet.
  2. 2. OFFER – The server offers an IP address plus mask, gateway, DNS server and lease time.
  3. 3. REQUEST – The device accepts one offer.
  4. 4. ACK – The server confirms and records the lease.
  5. 5. Use and renew – The device configures itself and renews the lease before it expires.

Why it matters

Remember the four messages as DORA: Discover, Offer, Request, Acknowledge. DHCP uses UDP ports 67 (server) and 68 (client).

Attacks: a rogue DHCP server can hand out a fake gateway or DNS server so traffic goes through the attacker. DHCP starvation floods the server with requests until the pool is empty.

Defences: DHCP snooping on switches (only trusted ports may answer), limits on addresses per port, and using HTTPS/VPN anyway. If a device shows an address like 169.254.x.x, DHCP failed and it assigned itself one.
