Buffer Overflow

Watch input fill a small memory box, spill into its neighbours, and see why that is dangerous. (Simplified view of memory.)

THE C CODE
Input: (none yet)
buffer[8]
is_admin (4 bytes)return address (4 bytes)
is_admin = 0x00000000
return address = 0x0804AB12

What just happened?

The step you are on lights up here.

  1. 1. Input that fits – "HELLO" plus the invisible \0 end marker is 6 bytes, which fits in the 8-byte buffer. Nothing else changes.
  2. 2. Overflow into a variable – 9 characters plus \0 is 10 bytes. The extra bytes spill into the next variable, is_admin, and make it non-zero.
  3. 3. Overwrite the return address – A longer input reaches the return address, which tells the CPU where to go when the function ends. Now an attacker controls where the program jumps.
  4. 4. The fix – Copy at most 7 bytes and always end the string. Extra input is cut off and nothing else in memory is touched.

Why does security care?

If the attacker puts the address of their own code into the return address, they can run it. Buffer overflows have been behind real attacks for decades, including the 1988 Morris worm.

Defenses: check lengths in code, use memory-safe languages (Rust, Java, Python), and rely on protections like stack canaries, ASLR (random addresses) and DEP/NX (non-executable stack).

Practice only on your own machines or training platforms such as pwn.college.
