What just happened?

The step you are on lights up here.

  1. 1. SYN – "I want to connect." The client sends a random starting number x. The sequence number is a counter that keeps data in order and spots lost pieces.
  2. 2. SYN-ACK – "Got it, and I'm ready too." The server confirms x (by sending x + 1) and sends its own number y. Once this arrives, the client knows the server is reachable.
  3. 3. ACK – "Got yours too." The client confirms y (by sending y + 1). Only now does the server know the client can hear it, so the server becomes ESTABLISHED.
  4. 4. Data flows – Both sides are ESTABLISHED, so real data (a web page, a message) can now be sent in both directions.

Why does security care?

SYN flood: an attacker sends thousands of SYN packets and never sends the final ACK. The server keeps every half-open connection waiting until it runs out of room and real users cannot connect. Defenses include SYN cookies and rate limiting.

Port scanning: tools like Nmap send a SYN and watch the reply. A SYN-ACK means the port is open; a reset (RST) means it is closed.
