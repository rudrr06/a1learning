File Permissions (chmod)

Every Linux file has three sets of locks. See how ls -l and chmod control them.

What just happened?

The step you are on lights up here.

  1. Three classes, three rights – Owner, group, others × read, write, execute.
  2. Reading ls -l – First character = type (- file, d folder). Next 9 = rwx for owner, group, others.
  3. The numbers – r=4, w=2, x=1. Add them for each class: 644, 600, 755…
  4. Others can read – Anyone not the owner or in the group falls under "others".
  5. chmod 600 – Keep private files private: owner only.
  6. Permission denied – The kernel enforces the permissions every time.
  7. Execute needed – Scripts and programs need x to run.
  8. chmod u+x – Symbolic form: u (user), g (group), o (others), a (all), with + or -.
  9. It runs – Now the owner can run the script.
  10. chmod 777 – Too open: a classic security mistake.

Why it matters

Permissions are the first wall protecting a Linux system. Wrong ones leak passwords, SSH keys and config files.

Security: attackers look for world-writable files, scripts they can edit that run as root, and readable secrets. Use the least permission that works: files 644 or 600, scripts 755, private keys 600.
