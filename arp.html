ARP

On a local network, frames are delivered using MAC addresses. ARP is the phone book that connects IPs to MACs.

What just happened?

The step you are on lights up here.

  1. 1. Look up – A device checks its ARP cache before asking the network.
  2. 2. Request – ARP request is a broadcast: "who has this IP?"
  3. 3. Others ignore – Only the device with that IP replies.
  4. 4. Reply and cache – The reply is a unicast and gets stored in the cache.
  5. 5. Spoofing – Anyone can send a fake ARP reply, and most devices accept it.

Why it matters

ARP works only inside one local network (one broadcast domain). To reach a device on another network, your PC ARPs for the default gateway's MAC, not the faraway server.

ARP spoofing / poisoning lets an attacker sit in the middle (read or change traffic), or just drop it to cause an outage. Tools like Ettercap and arpspoof automate this, so only test it on your own lab (like your VirtualBox network).

Defences: Dynamic ARP Inspection (DAI) on managed switches, static ARP entries for critical devices, port security, and using HTTPS/VPN so intercepted traffic is still encrypted.
