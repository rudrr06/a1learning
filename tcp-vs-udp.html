What just happened?

The step you are on lights up here.

  1. 1. Sending – Packets are sent. One is lost on the way.
  2. 2. TCP notices – Missing acknowledgements (ACKs) tell the TCP sender that a packet is lost. UDP has no ACKs.
  3. 3. Retransmit – TCP sends the lost packet again. UDP does not.
  4. 4. Result – TCP delivers everything in order. UDP delivers what arrived.
  5. 5. Which to use – TCP for correctness, UDP for speed and low delay.

Why it matters

TCP adds: a connection (handshake), sequence numbers, acknowledgements, retransmission, ordering, and flow and congestion control. Header: at least 20 bytes. UDP: just ports, length and checksum. Header: 8 bytes.

Typical uses: TCP for web (HTTP/HTTPS), email, SSH, file transfer. UDP for DNS, DHCP, VoIP, video calls, gaming, streaming and VPNs like WireGuard. HTTP/3 (QUIC) runs on UDP and adds its own reliability.

Security link: UDP has no handshake, so the source address is easy to spoof. That enables reflection and amplification DDoS attacks (DNS, NTP): a small spoofed request makes a server send a big response to the victim. TCP's handshake is abused by SYN floods instead.
