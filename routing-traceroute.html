Routing & Traceroute

Every packet has a TTL that shrinks at each router. Traceroute cleverly uses that to discover the route.

What just happened?

The step you are on lights up here.

  1. 1. TTL 1 – The first probe dies at the first router, which reports itself.
  2. 2. TTL 2 – The second probe dies at the second router.
  3. 3. TTL 3 – This probe reaches the destination, so the path is complete.

Why it matters

Routing: each router has a routing table (networks and the next hop to reach them) and picks the longest prefix match, meaning the most specific route wins. If nothing matches, it uses the default route. Routers learn routes by hand (static) or from protocols like OSPF inside a company and BGP between ISPs.

Tools: tracert on Windows, traceroute on Linux and macOS. A line of * * * means a router did not answer, often because a firewall blocks ICMP.

Security link: traceroute is a classic recon tool: it reveals network layout, firewalls and ISPs. The TTL also prevents packets from looping forever if routers are misconfigured. BGP hijacking, where someone announces routes they do not own, can redirect internet traffic.
