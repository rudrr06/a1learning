The OSI Model

Follow a message from your keyboard to your friend's screen. Each layer wraps the data with its own information.

SENDER (YOU)
RECEIVER (FRIEND)
THE DATA RIGHT NOW:

What just happened?

The step you are on lights up here.

  1. 7. Application – The layer apps use to talk to the network (HTTP, DNS, SMTP). Your message is created here.
  2. 6. Presentation – Formats, compresses and encrypts the data so both sides understand it.
  3. 5. Session – Opens, manages and closes the conversation between the two computers.
  4. 4. Transport – Splits data into segments, adds port numbers, and (with TCP) makes delivery reliable.
  5. 3. Network – Adds IP addresses and chooses the route across networks. The unit is a packet.
  6. 2. Data Link – Adds MAC addresses for the next hop on the local link. The unit is a frame.
  7. 1. Physical – Sends raw bits as electrical, light or radio signals.
  8. Receiver unwraps – The receiver goes bottom to top and removes each layer's header (decapsulation) until only your message is left.

Why it matters

The OSI model is a shared language: when someone says "a layer 2 problem" or "a layer 7 attack", you instantly know where to look.

Security link: attacks and defences map to layers. ARP spoofing is layer 2, IP spoofing and routing attacks are layer 3, SYN floods are layer 4, SQL injection and phishing are layer 7. Firewalls, switches and routers each work at different layers.

Memory trick (top to bottom): All People Seem To Need Data Processing: Application, Presentation, Session, Transport, Network, Data Link, Physical. The real internet uses the simpler 4-layer TCP/IP model, but OSI is the standard way to learn and talk about it.
