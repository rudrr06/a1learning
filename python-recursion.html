Recursion: A Function Calling Itself

Factorial (3 × 2 × 1) done by a function that calls itself. Watch the stack on the right.

🐍 Try it yourself

Real Python runs right here in your browser. Try: factorial(10), or remove the base case (the if n == 1 part) to see a RecursionError. Press Ctrl+Enter to run.

The first run downloads Python (about 10 MB), then runs are instant. input() is not supported here.

What just happened?

The step you are on lights up here.

  1. The idea – Solve a big problem by solving a smaller copy of it.
  2. First call – Each call gets its own box on the stack.
  3. Calls itself – It waits for the smaller answer.
  4. Deeper – The stack grows.
  5. Base case – The stopping rule. Every recursion needs one.
  6. Unwinding – Answers flow back, one box at a time.
  7. Final multiplication – The first call finishes last.
  8. Result – The stack is back to main.

Why it matters

Recursion is natural for things that contain smaller copies of themselves: folders inside folders, family trees, searching, some maths.

Security link: a recursion with no base case, or one that goes too deep, overflows the call stack and crashes the program. Attackers who can make a program recurse endlessly (with crafted input) can cause denial of service. This is the same stack you saw in the buffer overflow topic.
